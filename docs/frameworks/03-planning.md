# 업무·기획 프레임워크

## 진행 체계

문제 정의 → 범위·성공 기준 → 화면·API 합의 → 작업 배분 → 구현·검증 → 검토·출시 → 결과 확인.

각 단계는 문서 분량보다 다음 담당자가 실행할 수 있는 정보가 있는지로 판단합니다. 미정 항목에는 결정 담당자와 기한을 적습니다.

## 1. 프로젝트 정의서

| 항목 | 작성 틀 |
|---|---|
| 프로젝트·담당자 | 이름 / 의사결정 책임자 / 참여자 |
| 사용자와 문제 | 누가 어떤 상황에서 어떤 불편을 겪는가 |
| 목표 | 어떤 사용자 행동·결과를 개선할 것인가 |
| 성공 지표 | 지표 정의 / 현재값 / 목표값 / 측정 방법 / 측정일 |
| 포함 범위 | 이번에 제공하는 기능 |
| 제외 범위 | 후속 작업으로 남길 기능 |
| 제약 | 일정·예산·데이터·인력·외부 서비스 |
| 산출물 | 화면, API, 데이터, 운영 문서 |
| 완료 판단 | 검증 증거와 최종 검토 담당자 |

FactoryPick 예시(계획 예시이며 합의된 목표가 아님): 지역·업종에 맞는 공장을 찾는 사용자가 검색과 지도에서 같은 결과를 보도록 개선한다. 지표는 대표 사용자 시나리오의 탐색 성공률과 검색 응답 시간을 측정해 정한다.

## 2. 기능 정의서 — 기능마다 복사

```text
요구사항 ID: REQ-___
기능명:
사용자 / 사용 상황:
문제와 기대 결과:
우선순위: 필수 / 다음 / 보류
포함 범위:
제외 범위:
화면·입력·출력:
API·DB 영향:
인증·권한:
정상 흐름:
빈 결과·오류·예외 흐름:
완료 조건(관찰 가능한 행동으로):
관련 작업 ID:
담당자 / 검토자:
미정 사항 / 결정 담당자 / 결정 기한:
```

예시 REQ-001: 지역별 공장 조회.

- 사용자가 지역을 선택하고 검색하면 목록과 지도에 동일한 지역 조건이 적용됩니다.
- 검색 조건 변경 시 목록이 첫 페이지로 돌아가고 이전 선택 공장 상세가 해제됩니다.
- 결과가 없으면 빈 결과 안내, API 실패 시 오류 안내를 표시합니다.
- 지도 키가 없으면 지도 설정 안내를 표시하고 목록 조회는 사용할 수 있습니다.
- 성공 여부는 정상·빈 결과·실패·빠른 조건 변경 시나리오로 판단합니다.

## 3. 작업 분해·담당표

아래 행은 REQ-001의 계획 예시이며 현재 구현 완료 여부를 나타내지 않습니다.

| ID | 요구사항 | 작업·산출물 | 담당 | 선행 작업 | 크기 | 완료 증거 |
|---|---|---|---|---|---|---|
| TASK-01 | REQ-001 | 지역 필터와 상태 흐름 정의 | 미정 | 없음 | S | 화면·상태 합의 |
| TASK-02 | REQ-001 | 검색·마커 API 계약 확인 | 미정 | TASK-01 | S | 파라미터·응답 합의 |
| TASK-03 | REQ-001 | UI·조회 연결 | 미정 | TASK-02 | M | 동작 화면·검증 결과 |
| TASK-04 | REQ-001 | 복합 필터 검증 | 미정 | TASK-02 | M | 관련 테스트 결과 |
| TASK-05 | REQ-001 | 통합 검토·문서 갱신 | 미정 | TASK-03,04 | S | 시나리오 결과·PR |

S/M/L은 상대 크기입니다. L 작업은 하루 이틀 단위로 검토 가능한 산출물로 나눕니다. 일정은 담당자 가용 시간과 선행 작업을 확인한 뒤 확정합니다.

상태: 대기 → 진행 → 검토 → 완료. 장애가 있으면 상태 옆에 원인·해결 담당자·다음 확인일을 기록합니다.

## 4. 일정·운영 틀

| 단계 | 시작·종료 | 종료 조건 | 담당 |
|---|---|---|---|
| 요구사항 | 미정 | 범위·성공 지표 합의 | 미정 |
| 설계 | 미정 | 화면·API·데이터 계약 합의 | 미정 |
| 구현 | 미정 | 기능별 완료 조건 충족 | 미정 |
| 통합 검증 | 미정 | 대표 흐름과 실패 흐름 확인 | 미정 |
| 출시·평가 | 미정 | 배포 확인·지표 수집·후속 결정 | 미정 |

진행 중에는 완료한 산출물, 다음 작업, 막힌 이유와 필요한 결정만 공유합니다. 범위가 늘면 추가 비용·일정 영향을 기록하고 무엇을 미룰지 함께 정합니다.

## 6. 검토·완료 틀

```text
PR 또는 결과물 제목:
해결하는 사용자 문제:
변경 후 동작:
관련 요구사항·작업 ID:
검증한 시나리오·결과:
실행하지 못한 검증과 이유:
화면·API·DB·환경변수 변경:
남은 제약·후속 작업:
```

기능 완료는 요구사항 충족, 관련 검증 통과, 오류·권한 동작 확인, 문서 갱신, 팀 검토까지로 정의합니다. 출시가 포함된 작업은 배포 환경 확인과 복구 방법도 완료 조건에 넣습니다.

출시 후에는 목표 지표의 실제값을 기록하고 유지·개선·중단 중 다음 행동을 정합니다. 측정할 수 없었던 지표는 원인과 다음 측정 방법을 남깁니다.
