# FactoryPick 개발·기획 프레임워크

프로젝트의 웹 개발, 백엔드 개발, 업무·기획을 같은 기준으로 진행하기 위한 실무 문서입니다. 새 프레임워크 라이브러리를 만드는 대신 현재 React·Spring Boot 코드에 맞춰 개발 구조와 재사용 가능한 작성 틀을 정의합니다.

| 문서 | 사용할 때 | 주요 산출물 |
|---|---|---|
| [웹 개발](01-web.md) | 화면·필터·지도·관리 기능을 만들 때 | 컴포넌트 책임, 상태 흐름, 화면 코드 예시, 검증 기준 |
| [백엔드 개발](02-backend.md) | API·DB·인증·외부 연동을 만들 때 | 계층별 책임, API 계약, 서비스 코드 예시, 검증 기준 |
| [업무·기획](03-planning.md) | 기능을 정의하고 작업을 배분할 때 | 요구사항, 작업표, 일정, 위험·의사결정 기록, 완료 기준 |

## 공통 진행 순서

1. 업무·기획 문서의 기능 정의서를 복사하고 사용자·문제·성공 기준을 적습니다.
2. 요청·응답·오류·인증 조건을 백엔드 API 계약서로 합의합니다.
3. 웹 문서에서 화면 상태와 담당 컴포넌트를 정합니다.
4. 작업을 담당자와 완료 기준이 있는 작은 단위로 나눕니다.
5. 구현 후 관련 검증 결과를 PR에 기록하고 팀 검토를 받습니다.

예: “지역 필터 추가” → 필터 선택 시 페이지 초기화 정의 → 검색·마커 API에 같은 조건 전달 → 정상·빈 결과·오류·빠른 조건 변경 확인.

## 현재 프로젝트와의 관계

- 프런트엔드: React 19, Vite 8, JavaScript. 정확한 의존성은 [package.json](../../frontend/package.json)과 lockfile을 기준으로 합니다.
- 백엔드: Java 17, Spring Boot 3.5.7, Spring JDBC, MySQL. [build.gradle](../../backend/build.gradle)이 기준입니다.
- 문서의 코드 블록은 구현 시 복사·수정하는 예시이며 자동으로 앱에 등록되지 않습니다.
- 기존 실행 방법은 [프런트엔드 안내](../../frontend/README.md), [백엔드 안내](../../backend/README.md)를 참고합니다.
- 팀 브랜치·PR 절차는 [저장소 협업 안내](../../README.md)를 따릅니다.

## 실행·검증 명령

PowerShell에서 저장소 루트를 기준으로 별도 터미널 두 개를 사용합니다.

백엔드(MySQL 및 환경 설정 준비 후):

```powershell
cd backend
.\gradlew.bat bootRun
```

프런트엔드:

```powershell
cd frontend
npm ci
npm run dev
```

브라우저는 http://localhost:5173, 상태 API는 http://localhost:8080/api/health 입니다. 프런트엔드 개발 서버가 /api 요청을 백엔드로 프록시합니다.

검증은 변경 범위에 맞게 선택합니다. 프런트엔드 코드 변경은 npm test, npm run lint, npm run build를 실행하고, 백엔드 코드 변경은 backend에서 .\gradlew.bat test를 실행합니다. DB 변경은 별도의 테스트 DB를 사용하는 통합 검증이 필요합니다. 문서만 변경한 경우 링크·명령·코드와 실제 구현의 일치 여부를 확인합니다.
